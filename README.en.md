# renpy-toolkit — Ren'Py authoring & localization toolkit

A toolkit for **authoring assistance** and **translation (localization)** of Ren'Py
games. Pure Python standard library; it does not depend on Ren'Py itself.

It grew out of four upstream projects and the official Ren'Py documentation:

| Upstream | What it provided |
| --- | --- |
| [renpy/renpy](https://github.com/renpy/renpy) | The engine. Translation identifier generation, string tables, the official `translate` generator, the text-tag table, archive load priority. |
| [Dclef/renpy-tl](https://github.com/Dclef/renpy-tl) | A field checklist for Chinese localization: which checks matter, punctuation rules, font replacement. |
| [ZYKsslm/RenPy-Tutorial](https://github.com/ZYKsslm/RenPy-Tutorial) | A Chinese tutorial for the authoring side. |
| [CensoredUsername/unrpyc](https://github.com/CensoredUsername/unrpyc) | A reference `.rpyc` decompiler (this project uses a whitelisting pickle VM instead). |
| [Ren'Py docs](https://www.renpy.org/doc/html/) | Translation mechanics, CLI, custom text-tag semantics. |

No upstream code is imported; every rule is traced back to an engine fact and cited in
[`docs/`](docs/README.md).

├── exe/                    the GUI (separate release line, not shipped) — DEPRECATED
│   ├── gui.py              local HTTP server + system-browser window
│   ├── ui/index.html       the interface
│   └── tests/              39 pure-logic tests for the GUI
├── docs/                   reference notes (engine facts, format specs)
├── tools/                  build_release / build_portable / build_exe / make_release / check_*

`dsh-plugin/dsh-renpy-toolkit/` is the only real source; `dist/` is generated by
`tools/build_*.py` so the installed copy and the released copy can be compared
byte for byte.

## Three independent release lines

The three artifacts stand alone: **the exe does not depend on the plugin or the
skill, and neither of them contains or invokes the exe.**

| Line | Artifact | For | Start with |
| --- | --- | --- | --- |
| **Plugin / pip** | `renpy-toolkit` command + portable zip | Command line or the DSH plugin | `pip install .` (add `[all]` for Excel/fonts); or unzip the portable zip and run `python renpy-toolkit.py --help` |
| **agent skill** | `skills/renpy-toolkit/` | Let an AI assistant do the localization | Drop the whole directory into your skills directory |
| **Windows exe** (DEPRECATED) | `renpy-toolkit-exe-<version>.zip` | Clicking buttons, no command line | Unzip next to the game folder and double-click `renpy-toolkit.exe` |

**The plugin and the agent skill are the two lines we recommend.** They are the
main line: maintained, supported, cross-platform. The Windows exe is a one-off
convenience shell for people who will not touch a command line, and it is no
longer maintained.

### What each line is, and what it cannot do

| Line | Role | Limits |
| --- | --- | --- |
| **Plugin / pip** (recommended) | Where every feature lives; the only line that keeps receiving updates | Needs Python 3.8+ (or the runtime bundled in the portable zip); `tl gen` must use the target game's own interpreter, `lib/py3-*/python.exe` |
| **agent skill** (recommended for AI use) | No code — it teaches an AI assistant the same commands and judgement | Its ceiling is the plugin: with no toolkit on the machine it cannot run; if you copy the skill away, `scripts/rptk.py` must still find `dsh-plugin/dsh-renpy-toolkit` or you must set `RPTK_HOME` |
| **Windows exe** (DEPRECATED) | A GUI shell with the same features, frozen and no longer extended | Windows only; the UI runs in your system browser, and on some machines Edge's own "can't update" page covers it (use `--tab`); on some restricted accounts the bootloader cannot create its unpack directory, so rebuild with `--runtime-tmpdir` |

```bash
git clone https://github.com/AMeYunCloud/renpy-toolkit.git
cd renpy-toolkit
pip install .              # the renpy-toolkit command
pip install '.[all]'       # adds fontTools (font coverage) and openpyxl (XLSX)
```

It also runs without installing anything:
`cd dsh-plugin/dsh-renpy-toolkit && python -m renpy_toolkit --help`.
The plugin and the skill share one codebase and need only the standard library by
default; `fontTools` and `openpyxl` are optional and report a readable
`DependencyError` instead of failing at import. The **exe** is a separate line and
bundles both, so those two features work out of the box there — and conversely the
packages never contain or call the UI code.

### Windows exe (DEPRECATED)

> **DEPRECATED.** This line is no longer maintained: it is not released with new
> versions and receives no fixes. What follows describes the shape it had, for
> reference only; to use the GUI you must build it yourself with
> `python tools/build_exe.py --clean`, and the result is not verified against the
> current version. Use the two lines above (plugin / pip and agent skill) instead —
> both are command-line only.

This line is fully independent of the other two: the interface source lives in
`exe/`, the packages contain no UI code, and neither the plugin nor the skill ever
invokes the exe.

The window is a small local HTTP server opened as a **normal tab in your own
browser** (it reuses the browser you already have open — no new profile, no
WebView2, no native bindings); `renpy-toolkit.exe --app` gives a standalone
window instead. On start it scans the exe's own folder and one level below and
**only accepts real Ren'Py games**, decided by evidence (`RENPY RPC2` magic in
`game/*.rpyc`, `RPA-3.0` archives, a `renpy/` runtime, a bundled `lib/py3-*`
interpreter, a launcher that imports `renpy`, or Ren'Py source structure under
`game/`); a folder with a `game/` but none of that is listed as rejected with the
reason. It always shows a picker (zero, one or many games) and processes one game
at a time; with no game at all it tells you to move the exe next to the game
folder.

**Closing the page closes the tool**: the page sends a heartbeat every four
seconds and a `sendBeacon('/api/bye')` on `pagehide`; the server exits after 40
seconds without a request (120 while a task is running), so no process is left
behind. Three startup guards: a disk-root launch is refused with a modal that
counts down ten seconds and closes itself; a second instance is blocked by a
mutex; and the browser is only opened after the port really listens.

Only the translation skeleton is written into the game (`game/tl/<language>/`).
Everything else — logs, exported spreadsheets, decompiled scripts, backup
snapshots, scratch space — goes into `renpy-toolkit-数据/` beside the exe.

## Capabilities

### 1. Full skeleton generation (`tl gen`)

The official `translate` command only walks `.rpy` files that exist on disk, so for a
release that ships **only `.rpyc`** it produces just `common.rpy`. Community tools
silently drop sentences by heuristics such as "shorter than 8 characters".

`tl gen` takes another route: it **runs the game's own runtime** and reads the
translation units out of engine memory
(`renpy.game.script.translator.file_translates` and the SL2 screen tree).

```bash
cd dsh-plugin/dsh-renpy-toolkit
python -m renpy_toolkit tl gen <game> chinese --outdir work/tl --write
```

Measured on a 58,249-line release whose `game/` holds 50 `.rpyc` files and no sources:

```text
chinese: 58249 translate block(s), 2687 string(s) in 50 file(s)
wrote 53 file(s)            in 19.6s
```

The engine's own `lint` then reports `The chinese translation contains 58,249
dialogue blocks` — the same number as the original, exactly.

Skeleton bodies use the **source text as the placeholder**, never `""`: an empty
string is a valid translation, and `StringTranslator.translate()` returns it
(`if new is not None: return new`), which renders text as blank.

### 2. Binary assets

| Capability | Notes |
| --- | --- |
| `.rpyc` → `.rpy` | `pickletools`-based whitelisting VM, never `pickle.loads`; three-stage validation, 67,453 identifiers, zero differences |
| `.rpa` read/write | RPAv2 / RPAv3, XOR obfuscation and prefix slices; whitelisting `Unpickler`, 64 MiB inflate cap, Zip-Slip-safe entry names |

### 3. Translation quality

- **`verify`** — empty targets, tag/placeholder balance, mixed line endings, string
  conflicts, lost stutters, fullwidth quotes, statements outside blocks, unknown
  tags. Every check was tuned against real shipped translations.
- **`port`** — after a game update, move old translations into a new skeleton, keyed
  by identifier *and* source text, so blocks whose source changed are skipped
  (53,093 of 58,249 sentences carried over in one measured run).
- **`glossary`** — glossary-driven consistency checks and global rename.
- **`--backup-mode`** — every write keeps the old bytes first: `bak`, `git`
  (a shadow repo, restorable to any revision) or `none`. The shadow repo is a
  separate `--git-dir`: no `.git` appears in your translation folder and nothing is
  committed into your own repository. CRLF and BOM are byte-preserved.
  `tl backup list / show / restore / prune / size`.

### 4. Three kinds of text that "can't be translated"

| Kind | Why | What the toolkit does |
| --- | --- | --- |
| **Same string, different screens** | One `old` has one `new`, so "Enter" (go in) and "Enter" (the key) cannot both be right | Upstream answer is `{#context}`, which needs source edits; this tool generates a `translate <lang> python:` runtime patch keyed on `_current_screen` |
| **f-string** | It is evaluated *before* the translation lookup, so a template key never matches; adding a `strings` entry for it does nothing | `untranslatable` reports them; `fix-fstrings` emits `strings` entries or a regex patch, without touching the source |
| **Hard-coded fonts** | Font paths are literals inside the scripts | `font map` reports coverage and emits a `config.font_replacement_map` template |

## Development

```bash
cd dsh-plugin/dsh-renpy-toolkit
python -m unittest discover -s tests -t tests -q     # 548 passed
```

Build and verify the release artifacts:

```bash
python tools/build_release.py --verify   # re-hash and compare
python tools/build_portable.py --zip     # portable zip
python tools/build_exe.py --clean        # single-file Windows exe (DEPRECATED)
python tools/check_portable.py           # acceptance on a clean unzip
python tools/check_skill.py              # every documented flag really exists
python tools/check_readme.py             # anchors and relative links
```

## Requirements

- Python 3.10+ (standard library only). `fontTools` and `openpyxl` are optional.
- `tl gen` needs the game's own interpreter (`lib/py3-*/python.exe`); it must be
  produced by the target game's runtime.
- Git snapshots need git 2.15+; without it the `git` mode degrades to `.bak` and
  says so.
- The exe is Windows-only; the Python forms run on any platform.
