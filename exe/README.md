## 单文件包为什么把解包目录放在 exe 旁边

单文件 exe 启动时要把自己解包到临时目录。PyInstaller 的引导器会用「带自定义安全
描述符」的方式创建那个目录，在部分机器上（受限账户、组策略、安全软件）这一步直接
失败，弹 `Could not create temporary directory!`，表现为「第一次启动必然失败、第二次
偶尔成功」。

所以 `tools/build_exe.py` 给单文件包默认加了 `--runtime-tmpdir .` —— 解包到 exe 自己
所在的目录，不再依赖 `%TEMP%`。代价是启动瞬间在 exe 旁边生成一个临时子目录（退出后
自动清理），所以**不要把 exe 放在只读位置或磁盘根目录**（根目录由下面的危险路径闸拦）。

## 启动日志

窗口模式下看不到任何命令行输出，所以一切启动步骤都写进 exe 旁边的
`renpy-toolkit-启动.log`（带时间戳）。界面打不开时先看这个文件：最后一行就是卡住的
位置（服务就绪 / 打开浏览器 / profile 目录 / 界面已连接）。

## 打开界面：默认用你自己的浏览器

默认 `tab` 模式：把 `http://127.0.0.1:<随机端口>/` 交给你当前使用的浏览器，在已有的
窗口里开一个普通标签页 —— 不会新起一个干净的 profile，也就不会连带打开一堆扩展页。

只有 tab 模式 10 秒内没有任何请求到达时，才回退到独立窗口（`--app`），此时 profile 放在
`renpy-toolkit-数据/临时/browser`（exe 旁边），不碰 `C:\Users`。独立窗口看起来更像一个
应用，但需要 Edge/Chrome 的 `--app` 支持；如果你的 Edge 本身处于「无法更新」状态，
它可能弹出自己的更新提示页 —— 那是浏览器的问题，用 tab 模式即可绕开。

想强制某一种：`renpy-toolkit.exe --ui --tab` 或 `--ui --app`。

## 只处理 Ren'Py 游戏

界面在扫描阶段就走 `renpy_toolkit.engine.detect()`：没有 `RENPY RPC2` 编译脚本、
没有 `RPA` 归档、没有 `renpy/` 运行时、也没有 `lib/py3-*` 的目录不会出现在候选里，
并在列表下方给出「不是 Ren'Py 游戏」的原因。`select()` 也会再校验一次。

## 关掉网页就退出

页面每 4 秒发一次心跳，关闭时用 `sendBeacon('/api/bye')` 通知服务端；40 秒没有
请求就自己退出（有后台任务在跑时放宽到 120 秒），不会留下后台进程。

## 启动前的三道闸

启动顺序固定为：**危险路径 → 单实例 → 起服务 → 等端口就绪 → 开浏览器**。

- **危险路径**：所在目录若是盘符根（`C:\`、`E:\` 这类），弹一个置顶模态
  「危险路径：本工具停止工作」。该窗口没有标题栏、关不掉（拦 Alt+F4 与
  关闭请求），只有一个「退出」按钮，并在 **10 秒倒计时结束后自动结束进程**。
  理由：放在盘根运行时导出、备份、临时文件会散到盘根，误操作面也最大。
- **单实例**：用 Windows 命名互斥体（`Local\renpy-toolkit-gui`）挡住第二次启动，
  已有实例时弹「本工具已经在运行」，避免两个进程抢同一个数据目录。
- **等端口就绪**：先等 `127.0.0.1:<port>` 真的能连上，再打开浏览器。单文件包
  首次启动要解包（14 MB）+ 过一遍杀毒扫描，这段时间服务还没起来；抢在前面开
  浏览器只会得到一页「Failed to fetch」——这就是「第一次必然失败、第二次才好」
  的原因。页面侧也对只读调用做了重试（写操作不重试，避免重复执行）。

## 两种打开方式

| 方式 | 说明 |
| --- | --- |
| 默认 `--app` 窗口 | 无地址栏的独立窗口。profile 目录名**必须纯 ASCII**：带中文的 profile 路径会让 Edge 忽略它、退回用户默认 profile，于是用户装了扩展就会连带打开一堆扩展页。现在用 `browser-` 前缀，并额外加 `--disable-extensions` 双保险。 |
| `--tab` | 在用户**当前**浏览器里开一个普通标签页（复用已开窗口，不新起进程，因此不会有扩展页）。没有窗口可等，所以页面右上角有「退出工具」按钮，点它结束本地服务。 |

找不到游戏时，界面顶部会出现黄色横幅提示「请把 renpy-toolkit.exe 移到游戏文件夹
旁边（同级或上一级）」，选游戏区也给出同样说明。

## 界面

- 左栏顶部有一条粘顶的**上下文条**：当前游戏名 + 完整路径（过长省略，悬停看全文）+
  `语言 chinese`、`备份 bak` 两个 chip。没选游戏时整条变琥珀色并提示先选。
- 参数分两层：「目标语言 / 备份方式」是常用项；「Excel 文件 / 旧译本目录」收在
  「按需参数」子区块里，各自注明只被哪个按钮使用。填了 Excel 才能点「回填译文」，
  填了旧译本目录才能点「搬运旧译文」——按钮直接置灰并给出原因，而不是点了才报错。
- 每个操作按钮右上角有 `只读` / `会写入` 角标；分组标题带条目计数。
- **右侧日志按「每次指令」分组**，每组是一个可折叠的 `<details>`：
  - 折叠头一行：时间 · 指令名 · 结果胶囊（`完成 · 0.8s · 12 行` / `有问题` /
    `失败 · 退出码 1` / `运行中… 3s`）；
  - 组内正文等宽显示输出；命令本身（`$ renpy-toolkit …`）渲染成带竖线的子步骤条，
    一条指令含 preview+write 两条命令时能看出阶段推进；
  - **失败/有问题一定自动展开**并滚到该组顶部，同时组内顶部出现提示横幅；
  - 成功的那组保持展开，直到下一次点按钮才自动收起；用户手动点过的组不会被自动改动；
  - 工具条：`全部展开` / `全部收起` / `只看错误` / `清空`（清空只清界面，不动日志文件）。
- 长任务的输出是一次性刷出的（后端整段缓冲），所以进度用「转圈 + 秒表 + 不确定进度条」，
  不假装流式；输出过多时会保留头尾并注明「完整日志见文件」。

## 它做什么

- 启动后扫「exe 所在目录 + 一级子目录」里的 Ren'Py 游戏，列出卡片让你选一个；
  0 个、1 个、多个都会弹出这个窗口，一次只处理选中的那一个。
- 每个按钮都翻译成一次 `cli.main(argv)` 调用，所以界面行为与命令行完全一致
  （`--write` 语义、备份模式、退出码）。
- 除「生成汉化骨架」写进 `game/tl/<语言>/`，其余产物统一落在 exe 旁边的
  `renpy-toolkit-数据/`（日志、导出、反编译、备份、临时）。
- 「参数」里有四个输入：目标语言、备份方式、Excel 文件、旧译本目录。
  Excel 文件旁有「用最新导出的」，导出完直接一键填入，不用手抄路径。
- 报错给一行结论 + 可操作提示 + 退出码含义（1 有检查未通过 / 2 用法有误 /
  3 环境不具备）。「没有 .rpa 归档」「工程没有硬编码字体」这类**没东西可做**的
  情况不算失败，只在日志里说明。

## 为什么是「本地服务 + 系统浏览器」

冻结后的原生 WebView 绑定（pywebview + pythonnet）在 Windows 上要先解析 CLR，
PyInstaller 打包后实测失败（`Failed to resolve Python.Runtime.Loader.Initialize`）。
改用标准库 `http.server` 起一个只监听 `127.0.0.1` 的服务，再用系统 Edge/Chrome 的
`--app=` 窗口打开：没有原生依赖，也不需要 WebView2。

## 构建

必须在装了 PyInstaller 的解释器里跑（PyInstaller 只打包它自己 site-packages 里的东西），
`fontTools` 与 `openpyxl` 也要装在同一个解释器里：

```bash
python tools/build_exe.py --clean      # 打单文件 exe 并跑 --selftest 自检
python tools/build_exe.py --verify     # 只自检已有产物
```

已知限制：onefile 引导器要创建带自定义 ACL 的临时目录，在受限令牌环境里会被拒
（`Could not create temporary directory`）；此时用 `--runtime-tmpdir <可写目录>` 重建即可，
`build_exe.py --verify` 会把这种情况判为「环境受限」而不是失败。
